Week 8 · Keep Building

The Plan to Keep Building

A portfolio that never gets a second case study goes stale and stops proving anything new. This is the habit I'm setting up now, while the build context is still fresh — so the next update is a short conversation, not a rebuild.

Why this matters

The gap between a class artifact and a career platform is one simple habit.

Everything on my site right now — the identity kit, the voice, the case-study format — exists because I made a series of small, deliberate decisions across eight weeks. The risk isn't that I'll forget how to build; it's that without a plan, the site quietly stops growing the moment the internship ends. This document is that plan, written down while every decision is still easy to explain.

How to add the next case study

Six steps, reusing everything already built — no new design decisions required.

1

Open the Claude Project

It already holds my Voice Card, identity kit style note, and stack decisions — nothing needs re-explaining.

2

Drop in the raw material

A notebook, screenshots, or just a plain description of what happened — whatever exists at that point.

3

Ask for the three-beat shape

Problem → What I did → Outcome — the same structure every existing case study already uses.

4

Drop it into case-studies.html

Copy the existing .case card markup — same class, same structure — so it inherits the identity kit automatically.

5

Feature it, only if it earns it

Add one line to the Home page's "Featured case" section only if this becomes the strongest thing on the site.

6

Upload, commit, done

Same flat GitHub upload as every other update — no new tooling, no new setup.

The next real piece of work

Automated Forex Trading Bot — SMC + AI ensemble signal engine

Already in progress outside the internship, with real architecture and real trade-offs already made: a YAML-based config split across settings, risk, and strategy; a working Smart Money Concepts (SMC) signal engine with an ensemble confirmation threshold; demo-only mode locked behind a dual safety gate; and a maximum-drawdown ceiling that requires a manual resume rather than auto-recovering.

This doesn't need to be "finished" before it becomes a case study — it needs to be written up honestly at whatever stage it's actually at, the same way the FlyRank capstone case study reports a baseline that lost before reporting the model that won. The safety decisions alone (why demo-only, why a hard drawdown ceiling, why no auto-retraining) are a real "what I did" section on their own.

The reminder — keeping this from staying a good intention

A portfolio doesn't go stale because someone decides to stop updating it. It goes stale because there was never a fixed point to come back to. So instead of "whenever I feel like it," this gets a real cadence.

Monthly cadence

First Monday of every month — a fixed loop, not an open-ended intention.

Recurring reminder

What: "Add next case study to portfolio"

When: First Monday of every month, recurring

Where: Google Calendar, with a short description linking back to the six steps above

Evidence of the reminder being set (a screenshot of the recurring event) is the proof for this deliverable — not just the intention to set one.
